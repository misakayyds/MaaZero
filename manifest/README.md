# 发布清单

`manifest.schema.json`定义后台程序接受的版本1静态清单。`example-manifest.json`只用于展示字段和本地校验，其中的 `example.invalid` 地址按规范不可访问，不能直接发布。

`channels/`是待发布稳定/测试通道清单的仓库内源位置。CI后续把签名后的清单和`.sig`发布到GitHub Pages，大文件不放在这里。

正式清单必须：

- 通过JSON Schema结构校验。
- 额外通过后台程序的语义校验。
- 使用Ed25519签名，签名覆盖原始清单字节。
- 为每个文件记录精确版本URL、字节数和小写64位十六进制SHA-256。
- 为每个通道维护严格递增的`sequence`，设备不得接受低于本地已记录值的旧清单。
- 主地址和镜像地址指向完全相同的文件。
- 清单本身不保存凭证、私钥、Token或设备信息。

Schema只能约束结构，不能独立证明URL不可变、签名有效、版本兼容或下载文件可信，这些检查必须由 `maa-managerd` 完成。
