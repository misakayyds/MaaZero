# 小白用户流程

本文描述目标体验，当前尚无可刷模块，不是已验收安装教程。日常直接复用现有 WebUI，只新增“关于与模块设置”。

## 首次安装

用户只需要知道手机已经 Root，并能打开 Root 管理器。

1. 从项目 Release 下载 `MAA-Phone-Manager-vX.Y.Z.zip`。
2. 在 Magisk、KernelSU或APatch中选择“从本地安装”。
3. 安装器先检查 ARM64、Android版本、Root环境和基础可写目录；不兼容时在写入运行环境前停止。
4. 用户按提示重启手机。
5. 在模块页面点击“打开管理页面”。
6. WebUI显示设备检查结果、预计下载量、预计占用空间和数据目录。
7. 用户点击“一键安装”。
8. 后台依次完成清单验证、下载、哈希校验、Debian安装、maa-cli/MaaCore安装和项目配置。
9. 用户选择游戏客户端；默认稳定通道，定时任务显式开启，通知和培养可稍后配置。
10. 用户主动点击“连接测试”；首次安装不得自动启动完整日常任务。

## 安装页必须说人话

推荐状态：

- “正在检查手机是否兼容”
- “正在下载 Debian 运行环境，已完成 42%”
- “正在验证下载文件”
- “正在安装 MAA 组件”
- “安装完成，尚未运行游戏任务”

禁止只显示：

- shell退出码
- Python traceback
- MaaCore原始回调流
- 不说明影响面的“失败”

技术详情可以放入可展开区域，并提供“一键导出诊断包”。

## 日常使用

沿用现有首页、周计划、基建和培养页面，不重排已有导航。首页维持当前任务信息：

- 当前是否空闲、运行中或故障。
- 下一次计划任务时间。
- 最近一次任务是否成功。
- 游戏、MAA和网络连接状态。
- 当前版本及是否有稳定更新。
- 保留已有开始、停止、跳过下次等运行操作。

新增“关于与模块设置”集中管理版本、环境状态、安装、更新、回退、教程和脱敏诊断。后台能力未就绪时不能显示可执行的假按钮或伪造安装成功。

## 更新体验

1. WebUI显示更新内容、下载大小、是否需要重启以及可否回退。
2. 运行任务期间只下载，不切换版本。
3. 设备空闲后安装候选版本。
4. 健康检查成功才显示“更新完成”。
5. 失败时自动恢复上一版，并显示“已回退，原版本仍可使用”。

## 卸载体验

模块卸载默认只停止服务并移除启动入口，保留 `/data/local/maa-platform/data/`。彻底删除运行环境和用户配置必须在WebUI中单独确认，并在操作前显示将删除的确切目录和是否可恢复。
